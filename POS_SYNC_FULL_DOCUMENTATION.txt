一、 接口基础说明 (General Info)
--------------------------------------------------------------------------------
基础 Base URL: http://<服务器IP>:8008/api/v1/pos-sync
请求 Header:

  Content-Type: application/json


二、 POS 下载白名单数据接口 (`GET /api/v1/pos-sync/bootstrap`)
--------------------------------------------------------------------------------
HTTP 方法: GET
接口路径: /api/v1/pos-sync/bootstrap
功能说明:
  POS 终端一键启动或点击同步时调用，拉取当前业务员归属辖区内最新的白名单档案与资产池。
  POS 收到后保存至本地 SQLite 数据库，用于无网/弱网环境离线开户与续费交易。

三、 POS 离线数据批量上传接口 (`POST /api/v1/pos-sync/upload`)
--------------------------------------------------------------------------------
HTTP 方法: POST
接口路径: /api/v1/pos-sync/upload
功能说明:
  POS 终端恢复连网后，将离线积累的开户、资产变动、交易流水一次性上传给服务端。
  后端自动完成防重去重、客户 ID 冲突修复（Collision Healing）、资产一键绑定与平滑替换。

请求 Payload (JSON):
{

  // A. 离线新建客户 (新开户记录)
  "new_registrations": [

      "first_name": "Mary",
      "last_name": "Smith",

      "address": "Street 123",

四、 后端自动清洗与核心业务逻辑 (Internal Rules)
--------------------------------------------------------------------------------
1. 空值智能清洗 (Null Value Normalization):
   POS 端传入的 "-", "", "null", "NULL", "None" 等无意义空字符，后端统一自动清洗为 Python/SQL 中的 NULL/None，绝不造成数据库垃圾污染。

2. ID 冲突自愈机制 (Collision Healing):
   若离线新建的客户 UUID 在服务端冲突，后端会自动分配全局唯一新 ID，并同步修复该批次中的交易流水和资产绑定。

3. 资产替换与继承规则 (Asset Replacement):
   a. 只换 PV 板: 旧 PV 标记为 3 (Damaged 报废)，新 PV 激活并绑给主机与客户。
   b. 只换主机: 旧主机解绑报废，新主机自动继承原客户未损坏的旧 PV 板序列号。
   c. 零流水绑定: 即使 transactions 数组为空 []，单纯上传资产绑定也会 100% 成功执行。


五、 POS App 交互与缓存清理规范 (Client UI & Cache Specs)
--------------------------------------------------------------------------------
1. 缓存清理触发时机 (Cache Clearing Timing):
   a. 开卡/激活中断/中途退出场景:
      当业务员在开卡流程中取消或退回到【开卡设备列表】界面时，POS 客户端必须立即清理本次开卡流程中产生的临时表单与扫描缓存，防止残留数据污染下一次开卡。
   b. 开卡/激活成功场景:
      当开卡/激活流程顺利完成，业务员在“成功页”点击【返回首页】按钮时，POS 客户端清理本次开卡缓存并重置状态。

2. UI 按钮界面调整 (UI Button Removal):
   a. 移除【给其他人充值 (Recharge for Others)】功能按钮/菜单入口。
